Slide 7

Mémoire et processeurs virtuels

Combien allouer à AD1 et AD2 ?

💾

Mémoire de démarrage

2048 Mo recommandés pour un contrôleur de domaine en labo. La mémoire dynamique peut ajuster à la baisse une fois le service stable.

🧮

Processeurs virtuels

2 vCPU suffisent largement pour AD1/AD2 en environnement de test : inutile de sur-allouer sur un hôte partagé.

⚖️

Rappel du dimensionnement (Séance 2)

Avec 2 Go par DC, il reste une marge confortable sur les 16 Go recommandés pour l'hôte, même une fois SV1, SRVCore et CL10-01 ajoutés en Séance 4.

Slide 8

Disques durs virtuels (VHDX)

Taille fixe ou dynamique ?

📏

Taille fixe

Espace disque réservé intégralement dès la création. Performances légèrement supérieures, mais consomme tout l'espace immédiatement.

📈

Taille dynamique

Le fichier VHDX grossit au fur et à mesure des besoins réels. Idéal pour un bac à sable où l'espace disque de l'hôte est limité.

📌

Choix du cours

VHDX dynamique de 60 Go pour AD1 et AD2 : largement suffisant pour un contrôleur de domaine de labo, sans gaspiller l'espace disque de l'hôte.

Slide 11

Desktop Experience ou Core pour AD1/AD2 ?

Un choix pédagogique assumé

Pour cette maquette de cours, AD1 et AD2 seront installés en Desktop Experience : l'interface graphique facilite l'apprentissage des premières manipulations AD DS avant de pratiquer Server Core sur SRVCore (Séance 4).

🖥

AD1 et AD2

Desktop Experience — pour apprendre visuellement avant d'automatiser en PowerShell.

⌨

SRVCore (Séance 4)

Server Core — pour pratiquer l'administration sans interface graphique, une fois les bases acquises.

💡

À retenir

Le choix Core/Desktop Experience se fait à l'installation ; il est possible d'en changer après coup, mais cela demande une réinstallation ou une conversion avancée — mieux vaut bien choisir dès le départ.

Slide 12

Post-installation : renommer le serveur

Sortir du nom générique WIN-XXXXX

🏷

Pourquoi renommer ?

Le nom généré automatiquement (WIN-XXXXXXX) n'est pas exploitable : AD1 et AD2 doivent porter leur nom définitif avant toute autre configuration.

🖱

Via l'interface graphique

Gestionnaire de serveur → Propriétés → Nom de l'ordinateur → Modifier, puis redémarrer pour appliquer le changement.

⌨

Via PowerShell

Rename-Computer -NewName "AD1" -Restart : plus rapide, reproductible, et utilisable aussi en Server Core.

Checkpoint avant la Séance 4

Un état stable à conserver

✅

Ce qu'il faut valider avant le checkpoint

OS installé et à jour, nom final appliqué, adresse IP statique fonctionnelle, ping réussi entre AD1 et AD2.

Pourquoi créer ce point de contrôle

AD1 et AD2 seront promus contrôleurs de domaine en Séance 7 : un point de retour propre facilite tout dépannage futur.

Checkpoint-VM -Name "AD1" -SnapshotName "OS-installe-post-config"

Vocabulaire clé

18 termes à maîtriser avant la Séance 4

Machine virtuelle

Instance de système d'exploitation isolée, exécutée par l'hyperviseur

Génération (VM)

Génération 1 (BIOS) ou 2 (UEFI) : détermine le firmware virtuel de la VM

UEFI

Firmware moderne remplaçant le BIOS, requis pour la Génération 2

Secure Boot

Vérification de l'intégrité du chargeur de démarrage à chaque démarrage

VHDX

Format de disque dur virtuel utilisé par Hyper-V

Taille fixe

VHDX dont l'espace disque est réservé intégralement dès la création

Taille dynamique

VHDX qui grossit progressivement selon les besoins réels

ISO

Image disque contenant les fichiers d'installation de l'OS

Ordre de démarrage

Séquence des périphériques que la VM tente de démarrer en premier

Server Core

Desktop Experience

Rename-Computer

Cmdlet PowerShell pour renommer un ordinateur

New-NetIPAddress

Cmdlet PowerShell pour attribuer une adresse IP statique

Passerelle par défaut

Adresse IP du routeur utilisée pour sortir du réseau local

Point de contrôle

Instantané réversible de l'état d'une VM (checkpoint)

Compte Administrateur

Compte local intégré avec tous les droits sur le serveur

Mémoire dynamique

Ajustement automatique de la RAM allouée à une VM

Post-installation

Ensemble des configurations effectuées juste après l'installation de l'OS

Slide 19

Mémo commandes

PowerShell — création et post-installation

Créer une VM Génération 2

New-VM -Name "AD1" -MemoryStartupBytes 2GB -Generation 2 -SwitchName "LAN-Labo"

Créer un VHDX dynamique

New-VHD -Path "D:\VMs\AD1\AD1.vhdx" -SizeBytes 60GB -Dynamic

Monter l'ISO d'installation

Set-VMDvdDrive -VMName "AD1" -Path "D:\ISO\WinServer2022.iso"

Démarrer la VM

Start-VM -Name "AD1"

Renommer le serveur

Rename-Computer -NewName "AD1" -Restart

Configurer l'IP statique

New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.10.10 -PrefixLength 24 -DefaultGateway 192.168.10.1

Slide 8

Créer CL10-01

Le poste client de la maquette

💻

Une VM à part

CL10-01 exécute un OS client (Windows 10/11), pas Windows Server : c'est le seul poste de la maquette dans ce cas.

🔐

Génération 2 recommandée

Comme les autres VMs, Génération 2 avec Secure Boot activé — les OS clients récents le supportent nativement.

📌

Ressources recommandées

2 à 4 Go de RAM et un VHDX dynamique de 60-80 Go suffisent pour un poste client de test, sans usage intensif ni logiciels lourds.

Slide 10

Gérer les points de contrôle

Créer, appliquer, supprimer

➕

Créer

Fige l'état complet de la VM (mémoire, disque, configuration) à un instant T, avant une manipulation risquée.

↩

Appliquer / restaurer

Ramène la VM exactement à l'état du checkpoint choisi : les modifications postérieures sont perdues.

🗑

Supprimer

Fusionne les données du checkpoint dans le disque courant : à faire une fois l'étape validée pour libérer l'espace.

Slide 11

Checkpoints standards vs de production

Une nuance importante sur les DC

Type

Fonctionnement

Recommandé pour

Standard

Capture l'état mémoire ET disque, comme une pause/reprise

VMs sans rôle sensible à l'horodatage

De production

Utilise VSS, sans capturer l'état mémoire (redémarrage propre au retour)

AD1, AD2 : évite la corruption de la base AD

⚠️

Important pour AD1/AD2

Restaurer un checkpoint standard sur un contrôleur de domaine déjà promu peut provoquer un « USN rollback » et corrompre la réplication AD : toujours utiliser les checkpoints de production sur les DC.

Slide 12

Bonnes pratiques des checkpoints

Un outil puissant, à utiliser avec méthode

🏷

Nommage explicite

« Avant-install-ADDS » plutôt que « Checkpoint 1 » : le nom doit dire ce que l'on s'apprête à faire.

🧹

Purge régulière

Supprimer les checkpoints obsolètes : ils consomment de l'espace disque et peuvent ralentir la VM.

🚫

Jamais en production réelle

Les checkpoints standards sont un outil de labo/test : à éviter sur des serveurs de production sans précaution VSS.

Slide 4

TCP/IP — Les 4 notions qui expliquent tout

Adresse IP

Identifiant unique de chaque appareil sur le réseau. Comme l'adresse postale de votre PC.

192.168.1.50 (réseau local privé) 8.8.8.8 (serveur DNS public Google)

⚡ Deux appareils ne peuvent pas avoir la même IP sur le même réseau

Masque de sous-réseau

Définit le périmètre du réseau local — qui est 'dans' le même réseau.

255.255.255.0 = réseau /24 = jusqu'à 254 appareils 255.255.0.0 = réseau /16 = jusqu'à 65534 appareils

⚡ Même masque sur tous les PC d'un réseau local

Passerelle par défaut

L'adresse du routeur — la porte de sortie vers Internet.

192.168.1.1 (routeur typique résidence/PME) Sans passerelle = réseau local OK mais Internet impossible

⚡ Si impossible de pinguer la passerelle → câble ou Wi-Fi KO

Serveur DNS

Traduit les noms (google.com) en adresses IP numériques.

8.8.8.8 = Google DNS · 1.1.1.1 = Cloudflare DNS Sans DNS = Internet 'marche' (ping IP) mais sites inaccessibles

⚡ DNS défaillant : changer vers 8.8.8.8 résout 90 % des cas

Slide 5

DHCP vs IP statique — Quand utiliser chaque méthode

DHCP = le routeur attribue une IP automatiquement. IP statique = vous la saisissez manuellement et elle ne change jamais.

DHCP (Automatique)

Le routeur (serveur DHCP) attribue IP, masque, passerelle, DNS. Bail DHCP = durée d'attribution (souvent 24h ou 7 jours).

Avantages :

Aucune configuration · Évite les conflits IP · Idéal postes de travail

Limites :

IP peut changer à chaque bail · Impossible à localiser par IP fixe

Usage : PCs utilisateurs · Smartphones · Tablettes

IP Statique (Fixe)

Saisir manuellement : IP · masque · passerelle · DNS. L'IP ne change jamais — l'appareil est toujours joignable à cette adresse.

Avantages :

IP constante · Partage et accès directs · Essentiel pour certains services

Limites :

Configuration manuelle · Risque de conflits si mal gérée

Usage : Imprimantes réseau · NAS · Serveurs · Caméras IP · Routeurs

Bonne pratique : réservation DHCP par adresse MAC dans le routeur = IP 'quasi statique' sans config manuelle.

Slide 6

Méthode des 3 pings — Localiser une panne réseau en 3 min

Toujours dans cet ordre. Chaque résultat localise précisément où ça bloque. Ne jamais sauter d'étape.

1

ping [adresse passerelle]

ex: ping 192.168.1.1 — votre routeur

✓ Reply from 192.168.1.1 → câble/Wi-Fi OK · routeur accessible

✗ Request timed out · Destination host unreachable

→ Vérifier câble Ethernet ou reconnecter au Wi-Fi

2

ping 8.8.8.8

Serveur DNS Google — test Internet sans résolution DNS

✓ Reply from 8.8.8.8 → Internet fonctionnel · DNS peut être KO

✗ Request timed out (passerelle OK mais 8.8.8.8 KO)

→ Appeler le fournisseur Internet · Redémarrer le routeur

3

ping google.com

Test avec résolution DNS — si marche = tout est OK

✓ Reply from 172.217.x.x → DNS OK · tout fonctionne

✗ Request timed out (8.8.8.8 OK mais google.com KO)

→ Problème DNS uniquement → changer DNS vers 8.8.8.8

Slide 9

tracert et netstat — Outils de diagnostic avancé réseau

tracert [destination]

Trace le chemin des paquets de votre PC jusqu'à la destination, saut par saut.

Chaque ligne = 1 saut (routeur intermédiaire). Temps en ms × 3. '* * *' = saut ne répond pas (normal). Délai élevé = goulot d'étranglement identifié.

tracert google.com → voir si le délai explose chez l'opérateur Internet ou au-delà

netstat -an

Liste toutes les connexions réseau actives + ports en écoute.

ESTABLISHED = connexion active. LISTENING = port ouvert en attente. CLOSE_WAIT = connexion en cours de fermeture. TIME_WAIT = récemment fermée.

netstat -b (admin) = voir quel programme tient chaque connexion → repérer malware

netstat -rn

Affiche la table de routage Windows — comment les paquets sont dirigés.

Ligne 0.0.0.0 = route par défaut (passerelle). Métrique = priorité de la route. Utile quand plusieurs interfaces réseau coexistent (VPN + LAN).

Si 2 passerelles = conflits VPN → vérifier les métriques des routes

nslookup [nom]

Interroger le DNS manuellement pour résoudre un nom en IP.

nslookup google.com → voir quelle IP est retournée et depuis quel serveur DNS. nslookup google.com 8.8.8.8 → forcer un serveur DNS spécifique pour comparer.

Si résultat différent entre 2 DNS → cache DNS corrompu ou DNS menteur (ISP)

tracert = tracer route · netstat = connexions actives · nslookup = tester DNS · arp -a = table MAC/IP

Le Wi-Fi ce n'est pas juste 'branché ou pas'. Comprendre les fréquences explique 80 % des problèmes de performances.

Protocoles de sécurité Wi-Fi — du plus au moins sécurisé :

WPA3

Standard 2022+ · SAE remplace PSK · Résistant aux attaques dictionnaire — Recommandé si tous vos appareils le supportent

WPA2 (AES)

Standard depuis 2006 · CCMP/AES · Encore sécurisé — Utilisé par 90 % des réseaux Wi-Fi PME actuels

WPA (TKIP)

Obsolète · Vulnérable · Ne plus utiliser — Mettre à jour le firmware routeur

WEP

Cassable en quelques minutes · Complètement obsolète — Remplacer le routeur immédiatement

IP statique — Configurer une adresse fixe sous Windows

Utiliser une IP fixe pour les imprimantes, NAS, caméras IP — tout ce qui doit être joignable en permanence.

1

Ouvrir les paramètres réseau

Paramètres → Réseau et Internet → Wi-Fi ou Ethernet → Propriétés · OU: Centre réseau → Modifier les paramètres de la carte → Clic droit sur l'interface → Propriétés

2

Ouvrir IPv4

Sélectionner 'Protocole Internet Version 4 (TCP/IPv4)' → Propriétés

3

Saisir les valeurs

Cocher 'Utiliser l'adresse IP suivante' IP : ex. 192.168.1.100 (choisir hors plage DHCP) - Masque : 255.255.255.0 - Passerelle : 192.168.1.1 (adresse de votre routeur)

4

Configurer le DNS

Cocher 'Utiliser l'adresse de serveur DNS suivante' DNS préféré : 8.8.8.8 (ou IP du routeur) DNS auxiliaire : 8.8.4.4

5

Valider et tester

OK → OK → Fermer ping 8.8.8.8 → vérifier la connexion ping google.com → vérifier le DNS

6

Si conflit IP

Si un autre appareil a déjà cette IP → les 2 tombent en panne Choisir une IP en dehors de la plage DHCP du routeur (ex: 192.168.1.100-200)

Mémo diagnostic — Tous les scénarios réseau

1

Symptôme : Internet KO · Wi-Fi connecté · globe jaune

1. ipconfig /all → IP 169.254.x.x ? → DHCP KO → relancer routeur 2. IP normale → ping passerelle → ping 8.8.8.8 → ping google.com 3. Localiser le saut qui échoue → agir en conséquence

2

Symptôme : Sites lents · téléchargements normaux

1. nslookup google.com → temps de réponse > 200ms = DNS lent 2. Changer DNS → 8.8.8.8 et 8.8.4.4 → retester nslookup 3. ipconfig /flushdns → retester navigation

3

Symptôme : Wi-Fi se coupe toutes les heures

1. netsh wlan show interfaces → noter la bande (2.4/5 GHz) 2. Si 2.4 GHz → Essayer 5 GHz (moins d'interférences) 3. Vérifier paramètres éco-énergie : Ne pas couper Wi-Fi en veille

4

Symptôme : Imprimante réseau introuvable

1. ping [IP imprimante] → répond ? → driver manquant ou file bloquée 2. Ne répond pas → IP changée ? → redémarrer l'imprimante 3. Toujours attribuer une IP fixe aux imprimantes réseau

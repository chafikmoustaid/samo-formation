🔑 PARTIE 1 — ARCHITECTURE INTERNE D'UN COMPTE WINDOWS

1 — Nom visible (Username)

Le nom visible est l'étiquette affichée dans l'écran de connexion, C:\Users, gestion des comptes. ⚠️ Le nom visible n'est PAS l'identité réelle du compte. Windows travaille avec le SID. Si tu renommes un utilisateur : • Le nom change • Le dossier peut rester avec l'ancien nom • Le SID NE CHANGE PAS ✅ → Le nom visible = couche superficielle.

2 — SID (Security Identifier)

Identifiant unique attribué par Windows à chaque compte. Structure : S-1-5-21-XXXXX-XXXXX-XXXXX-1001 Windows associe au SID : • Permissions NTFS (fichiers/dossiers) • Droits dans le registre Windows • Accès réseau • Propriété des fichiers Cas terrain : ancien user supprimé → nouveau même nom → accès refusé. Pourquoi ? SID différent.

Schéma global : Nom visible → SID → Groupe → Droits locaux → Profil → Permissions NTFS Chaque couche dépend du SID — le SID est l'identité RÉELLE.

3 — Groupe d'appartenance

Un groupe est un conteneur de droits. Exemples : Administrateurs · Utilisateurs · Invités · Remote Desktop Users Permissions effectives = Somme des autorisations − Refus explicites 🔥 Refus prioritaire > Autorisation. Toujours. Cas : Jean ∈ Utilisateurs ∩ Administrateurs. Dossier refusé explicitement à Jean → Accès refusé malgré Admin.

6 — Droits locaux vs NTFS

Droit local = autorisation système (action Windows) Exemples : se connecter · arrêter · installer pilote · RDP → définis dans secpol.msc Permission NTFS = accès aux fichiers/dossiers uniquement Les deux utilisent le SID mais fonctionnent à des niveaux différents. ⚠️ Un administrateur peut toujours être bloqué par un refus NTFS explicite.

🔐 6 — DROITS LOCAUX — AUTORISATION SYSTÈME (≠ NTFS)

Qu'est-ce qu'un droit local ?

Un droit local est une autorisation système, pas une permission sur un fichier. Il donne le droit d'effectuer une action au niveau du système d'exploitation. Exemples de droits locaux : • Se connecter localement • Se connecter via Bureau à distance (RDP) • Arrêter le système • Installer / charger des pilotes de périphériques • Modifier l'heure système • Sauvegarder / restaurer des fichiers Où les trouver ? secpol.msc → Stratégies locales → Attribution des droits utilisateur Cas : Utilisateur a Contrôle total NTFS mais ne peut pas se connecter en RDP. → Ce n'est pas un problème NTFS — c'est un droit local manquant.

Piège fréquent — Admin ≠ tout permis

'Un administrateur peut tout faire.' FAUX. Un administrateur peut avoir tous les droits locaux, mais peut toujours être bloqué par un refus NTFS explicite. Exemple terrain : • Est administrateur • A contrôle total sur un dossier • MAIS ne peut pas modifier l'heure système Pourquoi ? Le droit local 'Modifier l'heure système' n'est pas attribué à son groupe. Résumé : Permissions NTFS → fichiers Droits locaux → actions système Les deux utilisent le SID — niveaux différents.

📁 PARTIE 2 — LES PROFILS UTILISATEURS

Profil ≠ Compte | Le profil est l'ENVIRONNEMENT du compte. Un compte peut exister sans profil. Un profil sans compte = dossier orphelin.

Structure du profil

C:\Users\NomUtilisateur ├── Desktop ├── Documents ├── Downloads ├── AppData │ ├── Local │ ├── Roaming │ └── LocalLow └── NTUSER.DAT ⚠️ NTUSER.DAT = ruche registre utilisateur. Chargé dans HKEY_CURRENT_USER à chaque connexion. Si corrompu → profil ne charge pas.

Processus de chargement

1 Windows authentifie le compte 2 Récupère le SID 3 Cherche SID dans ProfileList (registre) 4 Lit ProfileImagePath 5 Charge NTUSER.DAT 6 Monte l'environnement Si étape échoue → PROFIL TEMPORAIRE Registre : HKLM\...\ProfileList\SID → ProfileImagePath = C:\Users\Nom

Profil temporaire — causes

Message : 'Vous avez été connecté avec un profil temporaire.' Causes : • NTUSER.DAT corrompu • Mauvaise fermeture de session • Antivirus bloquant le chargement • Clé ProfileList corrompue • SID en double avec extension .bak Diagnostic : 1 Vérifier C:\Users\Nom existe 2 Ouvrir regedit → ProfileList 3 Chercher SID + SID.bak 4 Supprimer SID vide, renommer .bak → SID ⚠️ Les données sont souvent encore présentes ! Ne jamais supprimer le profil précipitamment.

💡 PROFIL — CAS TERRAIN ET ERREURS FRÉQUENTES

Coupure courant — pourquoi ça corrompt

Quand l'utilisateur est connecté, NTUSER.DAT est ouvert et Windows y écrit en permanence. Si l'électricité coupe : • Windows n'a pas le temps de fermer proprement la ruche • L'écriture est interrompue • Fichier laissé dans un état incohérent • Au redémarrage : Windows tente de charger NTUSER.DAT → structure invalide → profil temporaire Même cause pour un antivirus : Si l'AV analyse/bloque NTUSER.DAT au moment du chargement → Windows ne peut pas ouvrir la ruche → profil temporaire.

Supprimer un compte ≠ Supprimer le dossier

Supprimer un compte : • Supprime l'entrée dans SAM • Supprime le SID du système Mais Windows ne supprime PAS C:\Users\Nom (pour éviter perte accidentelle de données) Conséquence : si on recrée un user même nom : • Nouveau SID → accès refusé aux anciens fichiers Supprimer un compte supprime l'identité, pas l'environnement.

Problème

Cause technique

Coupure courant → profil temporaire

Antivirus → profil temporaire

Fichier verrouillé ou mis en quarantaine

Suppression compte → accès refusé

SID supprimé, dossier conservé — SID différent

Profil partiel

Comment Windows calcule les permissions effectives :

1 Windows récupère l'Access Token (SID user + SID groupes) 2 Compare tous les SID du token avec les ACE de l'ACL du fichier 3 Additionne toutes les autorisations (cumul des groupes) 4 Applique les refus explicites → ils écrasent toutes les autorisations

🔒 PARTIE 4 — PERMISSIONS NTFS EN PROFONDEUR

NTFS = système de fichiers Windows — il gère stockage, journalisation, chiffrement, compression et surtout les PERMISSIONS. Chaque fichier/dossier possède : un propriétaire (SID) + une ACL (Access Control List)

Structure ACL / ACE

ACL (Access Control List) = liste d'entrées ACE Chaque ACE (Access Control Entry) contient : • Un SID (utilisateur ou groupe) • Un type : Autoriser ou Refuser (Deny) • Un niveau d'accès (Lecture, Écriture, Contrôle total...) 🔥 Deny > Allow. Toujours. Sans exception.

Permission

Ce qu'elle permet

Lecture

Voir et copier les fichiers

Écriture

Créer, modifier

Modification

Lecture + écriture + suppression

Contrôle total

Tout + modifier les permissions elles-mêmes

Permissions avancées

Traverser dossier · Lire attributs · Prendre possession...

Héritage des permissions

Par défaut : dossier parent → sous-dossiers/fichiers. Permission explicite prime sur héritée. On peut désactiver l'héritage (→ convertir en explicites).

🔍 PARTIE 5 — DIAGNOSTIC PROFESSIONNEL PAR COUCHES

Règle d'or : diagnostiquer par couche — ne jamais sauter d'étage — un technicien ne 'tente pas', il vérifie.

1 Identifier l'utilisateur exact Quel compte connecté ? Local ou Microsoft ? Est-ce le bon ? → whoami

2 Vérifier les groupes Est-il vraiment admin ? Membre RDP ? → whoami /groups

3 Vérifier les droits locaux Peut-il se connecter ? Installer ? → secpol.msc → Attribution droits

4 Vérifier le profil Bureau vide ? Profil temporaire ? Dossier présent ? ProfileList ? SID.bak ?

5 Vérifier NTFS ACL correcte ? Refus explicite ? Héritage activé ? Propriétaire correct ?

6 Vérifier le propriétaire SID inconnu ? Ancien disque ? Migration système ? → Prendre possession

🧩 CAS GLOBAL NIVEAU N2 — ANALYSE COUCHE PAR COUCHE

Situation

Utilisateur ne peut pas accéder à D:\Finance • Est administrateur ✅ • A migré un ancien disque • Peut lire mais pas modifier • Bureau normal (pas de profil temporaire)

Analyse par couches

✅ Couche 1 — Compte : correct ✅ Couche 2 — SID : OK ✅ Couche 3 — Groupe Administrateurs : OK ✅ Couche 4 — Droits locaux : OK ✅ Couche 5 — Profil : OK ⚠️ Couche 6 — NTFS : SUSPECT ⚠️ Couche 7 — Propriétaire : SUSPECT

Conclusion et solution

Cause : ancien SID propriétaire des fichiers (disque migré) + permissions héritées incomplètes. Solution : 1) Prendre possession du dossier D:\Finance 2) Réappliquer les permissions pour le compte actuel 3) Vérifier héritage activé.

Erreur classique

Pourquoi c'est faux

❌ Réinstaller Windows

Le problème est dans l'ACL, pas dans l'OS

❌ Supprimer l'utilisateur

Changerait le SID — aggraverait le problème

❌ Désactiver UAC

Contourne la sécurité sans résoudre la cause

❌ Donner 'Contrôle total' partout

Mauvaise pratique — crée des failles de sécurité

❌ Ignorer le refus explicite

Il écrase toutes les autorisations — doit être traité

🧪 CAS PRATIQUES — CE QUE VOUS VERREZ SUR TEAMS

🧪 Exercice 1 — Bureau vide

Mise en situation : Utilisateur se connecte, bureau complètement vide, documents disparus. Questions : • Premier réflexe ? • C:\Users\Nom existe encore ? • Clé registre ProfileList ? 💡 Bureau vide = profil temporaire probable

🧪 Exercice 2 — Admin refusé NTFS

Mise en situation : Admin dit : 'C:\Finance : Accès refusé même en tant qu'admin.' Questions : • Quelle couche vérifier ? • Deny NTFS explicite ? • Comment prendre possession ? 💡 Admin ≠ tout permis → vérifier ACL

🧪 Exercice 3 — Pas de RDP

Mise en situation : Utilisateur a Contrôle total NTFS mais ne peut pas se connecter en RDP. Questions : • Quelle couche ? • Droit local ou NTFS ? • Quel groupe vérifier ? 💡 RDP = droit local, pas NTFS

✅ CORRIGÉS

Bureau vide → vérifier profil temporaire → ProfileList registre → chercher SID.bak → renommer clé SID.bak → SID Admin refusé → vérifier ACL → chercher Deny explicite → prendre possession du dossier → réappliquer les droits Pas RDP → vérifier droit local 'Autoriser la session via Bureau à distance' → ajouter au groupe 'Utilisateurs du Bureau à distance'

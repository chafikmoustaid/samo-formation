PHILOSOPHIE

Le diagnostic avancé — Lire les traces plutôt que deviner

Diagnostic de base (N1)

Redémarrer, vérifier les câbles Observer le symptôme visible Appliquer une solution connue

Suffit pour 80 % des cas courants

Diagnostic avancé (N2)

Consulter les journaux système Analyser un code d'erreur précis Isoler la cause avec un outil dédié

Nécessaire quand le symptôme ne suffit pas

Principe directeur

Windows documente presque tout ce qui plante Le fichier .dmp contient le nom du coupable Un technicien N2 sait où chercher la preuve

JOURNAL DE BORD

Observateur d'événements — Naviguer et filtrer

Accès

1

Ouvrir l'outil

Win+X → Observateur d'événements → Journaux Windows → Système.

2

Filtrer par gravité

Filtrer par « Critique + Erreur » sur les dernières 24 heures.

3

Chercher l'heure exacte

Se positionner autour de l'heure signalée par l'utilisateur.

Niveaux de gravité

4

Critique

Arrêt brutal du système — toujours investiguer en premier.

5

Erreur / Avertissement

Erreur = composant planté. Avertissement = à surveiller, pas urgent.

6

Information

Événements normaux (démarrage, MàJ) — utile pour confirmer une chronologie.

Slide 7

ANATOMIE D'UN CRASH

Comprendre un BSOD — Ce que l'écran bleu vous dit

Le code d'arrêt

Nom en majuscules type IRQL_NOT_LESS_OR_EQUAL Identifie une famille de cause précise Toujours noter le code exact avant de redémarrer

Le fichier concerné

Souvent un pilote (.sys) est nommé à l'écran Ce fichier pointe directement vers le coupable probable Rechercher ce pilote pour une mise à jour

Le QR code / adresse mémoire

Détails techniques pour analyse approfondie Peu utile sans outil d'analyse de dump WhoCrashed traduit cela automatiquement

Slide 13

TEST MATÉRIEL

MemTest86 — Procédure complète de diagnostic RAM

1

Télécharger l'image

memtest86.com → télécharger la version bootable USB.

2

Créer la clé USB

Utiliser l'outil fourni pour rendre la clé USB bootable.

3

Démarrer dessus

Redémarrer le PC et sélectionner la clé USB dans le menu de boot.

4

Lancer 2 passes minimum

Laisser tourner au moins 2 passes complètes — plusieurs heures possibles.

5

Interpréter

0 erreur = RAM saine. Toute erreur rouge = barrette à remplacer.

Alternative rapide intégrée à Windows : mdsched.exe (Diagnostic de la mémoire Windows)

Slide 15

FICHIERS DE CRASH

Fichiers dump — Types et emplacement

Mini dump

Petit fichier (~256 Ko), créé par défaut C:\Windows\Minidump\ Suffisant pour WhoCrashed

Kernel dump

Contient la mémoire utilisée par le noyau Plus volumineux, plus d'informations C:\Windows\MEMORY.DMP

Dump complet

Copie complète de la RAM au moment du crash Réservé aux cas très complexes / support Microsoft Nécessite beaucoup d'espace disque libre

Slide 16

BONNES PRATIQUES

Erreurs fréquentes en diagnostic avancé — À éviter

Précipitation

Réinstaller Windows avant d'avoir consulté les journaux Changer plusieurs composants à la fois Ignorer le code d'arrêt exact du BSOD

Mauvais ordre

Lancer DISM avant SFC sans raison Tester la RAM avant de vérifier les logiciels/pilotes Réinitialiser le PC sans sauvegarder d'abord

Documentation

Ne pas noter le code d'erreur avant de redémarrer Oublier de documenter les outils utilisés Ne pas indiquer si le problème est réellement résolu

Slide 17

PROGRESSION

Quand escalader un diagnostic N1 vers N2

Rester en N1

Symptôme résolu par redémarrage ou solution connue Cause identifiée en moins de 15 minutes Aucun BSOD, aucun fichier dump à analyser

Escalader vers N2

BSOD récurrent malgré une première tentative SFC/DISM ne résolvent pas le problème Cause probable = matériel (RAM, disque, carte mère)

Ce qu'il faut transmettre

Code d'arrêt exact et fréquence des crashs Actions déjà tentées et résultats obtenus Fichier .dmp le plus récent si disponible
